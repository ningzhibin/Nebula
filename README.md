## Nebula — notes

**Nebula** is the product name for this single-page intensity-matrix QC and visualization app (formerly described as “Data Matrix QC”). Place the app icon at **`image/Nebula_icon.png`** (favicon, touch icon, and header logo).

If you find Nebula useful, there is a **Buy me a coffee** button in the top-right header that links to PayPal (`ningzhibin@gmail.com`). Donations are entirely optional.

- **v5.57**: **Data PreProcess → Imputation — new "Seq KNN then MinProb (MCAR + MNAR hybrid)" method** - a two-stage imputer for the common case where sparsely-missing rows are missing at random but heavily-missing rows are not. Stage 1 runs Sequential KNN with the missing-% caps (fills only rows within the caps, treated as MCAR); Stage 2 runs MinProb on whatever Stage 1 left missing (the rows above the caps, treated as MNAR / below-detection), with MinProb's column statistics taken from the original observed values. Selecting it shows both parameter blocks; tune the caps to set the MCAR↔MNAR boundary.
- **v5.56**: **Data PreProcess → Imputation → Sequential KNN — added a per-group missingness cap; both caps default to 50%** - a new **Group by (meta column)** dropdown plus **Max missing % per group per row (skip above)** field. A row is left un-imputed if its overall missing % exceeds the row cap **or** if **any group** has a within-group missing % above the per-group cap (only when neighbor axis = Features/rows and a group column is chosen) - so features largely absent in a whole group aren't imputed across groups. Grouping reuses the same meta/replicate logic as the Group completeness filter. Both the row cap and the per-group cap now **default to 50%** (the row cap's previous default was 100%).
- **v5.55**: **Data PreProcess → Imputation → Sequential KNN — new "Max missing % per row (skip above)" cap** - a per-row missingness threshold (like `rowmax` in R's `impute.knn`/SeqKNN). Default **100** = impute every row. Set it lower (e.g. 50) to **leave very sparse rows un-imputed**: any row whose missing % (over the neighbor axis) exceeds the cap keeps its missing cells and is never used as a donor, so rows are not filled from just one or two observed values. The status line reports how many rows were skipped.
- **v5.54**: **Data PreProcess → Imputation — the KNN method is now Sequential KNN (SeqKNN)** - the nearest-neighbor imputer was upgraded from classic single-pass KNNimpute to **Sequential KNN (SeqKNN; Kim, Golub & Kim, *Bioinformatics* 2004)**. Rows are imputed **one at a time, starting from the row with the fewest missing values**; each imputed row is then added to the pool of complete donor rows, so more-missing rows can borrow from rows that were just filled (distances and donor values come from the progressively-completed matrix rather than a frozen original). All options carry over (K, distance metric, weighting, min. shared columns, fallback, neighbor axis). The UI is renamed to match: dropdown option **Sequential KNN (SeqKNN, MCAR)**, sidebar section **Sequential KNN parameters**, and status text like *"Sequential KNN: N / M rows imputed"*.

### CV variability filter documentation (v3.45)

- **Definition**: For each row, compute **CV = SD / mean** using only finite positive values (`>0`); zeros are treated as missing placeholders.
- **Threshold meaning**: Row is removed when **CV < threshold**. Default `0.2` means remove rows with less than **20% relative variability**.
- **Interpretation**: Lower CV rows are relatively flat across samples; higher CV rows show stronger relative spread.
- **Edge cases**: If a row has fewer than 2 positive values, SD is 0 and CV resolves to 0; such rows are typically removed for thresholds > 0.
- **Recommendation**: Start at `0.2`, then tune with the Summary histogram to balance noise removal vs signal retention.

### Group inference from sample names (v1.01)

Metadata Group column is auto-guessed from sample names using several rules:

- **Numeric pattern**: `1_1, 1_2, 2_1, 2_2` → groups 1, 2
- **Prefix pattern**: `A_1, A_2, B_1, B_2` → groups A, B
- **Even division**: When names lack group info (e.g. `Sample_1..Sample_15`), infers N = G × R (e.g. 15 → 5 groups × 3 replicates). Prefers R = 3, 2, 4, 5.
